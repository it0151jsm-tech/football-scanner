# Team identity and OU market audit

## Scope and source evidence (20 October 2026)

`scripts/audit_leagues.py` reads all 38 selectable `LEAGUES` and every configured Understat source, including context-only sources. It requests Football-Data CSV seasons 2627/2526 and Understat 2026 with fallback 2025. It never calls The Odds API. Current/previous source roster differences are labelled new source names, not independently verified promotions. Runtime Data Health checks only distinct API team labels already returned by the user's explicit scan, against the actual loaded CSV/xG frames. Opening cards, changing views and entering manual quotes request no external data.

The first live audit (run 39442842219) found 17 successful current CSV feeds, 9 configured feeds that failed to load, and 12 leagues with no configured CSV source. Among 96 Understat roster labels compared with current CSV rosters, 71 matched and 25 remained unresolved. This does **not** verify all Odds API labels: production SQLite/API payloads were unavailable and the source audit checked zero API labels. The checked-in summary states this scope. Full source rosters, HTTP statuses, source URLs and unresolved labels are in the CI artifact `iphone-dashboard-previews/league-source-audit.json`. No aliases inferred from spelling similarity were added. Existing Oxford United/Oxford and Wigan Athletic/Wigan aliases retain their recorded source evidence.

Data Health shows per-league observed API names, problem counts, source support, source roster/cross-match counts and audit times. Individual results distinguish matched, unmatched, unsupported, stale (>120 days/no earlier game), and load failure. A zero API count means unverified, never "all passed". These are dated observations, not continuously refreshed coverage claims. Failed configured source URLs require separate source validation before replacing them.

## Under selection and main OU line

The previous grouped selector ranked independently saved outcomes and ultimately broke ties by row ID. When Under was saved after Over, a tie could favour Under. The previous persistence key also replaced alternative lines for the same side/bookmaker. The legacy table/new-slip selector also preferred A score and then odds, independently of model availability. OU table rows now share the card assessment and show both prices as evaluation data; new OU slip suggestions require the same confirmed directional selection as the card. Existing saved slips and AH eligibility rules remain unchanged. Neither the unchanged Poisson nor EV function contains a blanket preference for Under. AH's internal 2.5 model reference is not used as an OU market quote. A real historical Under/Over selection rate cannot be recovered without the user's SQLite; the app now reports counts and proportions for the fixtures actually displayed (excluding neutral/unknown-main cards from directional percentages).

OU rows now retain each line. Each bookmaker uses its latest saved scan. A complete main-line candidate requires Over and Under at the same line, bookmaker and exact scan timestamp, decimal prices >1, a quarter-goal line, implied probability sum 0.98–1.20 and normalized price balance within 0.08 of 0.5. Rank candidate lines by the number of distinct supporting bookmakers, then mean balance. With equal support and balance gap <0.02, report unconfirmed. Within a selected line, show the most balanced eligible actual bookmaker pair. This is a documented conservative market estimate, not a feed's official main-line flag or a claim about every website. It does not assume proximity to 2.00 is sufficient.

Only after selecting the line does the card compare both sides. Both saved B/EV results must be valid for their exact price/line and share expected goals. Existing A support (>=55 and >=5 samples) plus positive EV is required; if both qualify, greater EV wins. EV ties remain neutral, never broken by row ID, odds or A score. Missing EV is explicitly a market under evaluation, not a betting recommendation. Form-only evidence retains the "แนวโน้มจากสถิติ — ยังยืนยันความคุ้มค่าราคาไม่ได้" label in details. All predictions remain uncalibrated.

The existing `spreads,totals` request is unchanged. Alternative lines are shown only when actually supplied and saved; no additional alternate-market endpoint/quota is requested. An incomplete or ambiguous set is labelled unconfirmed, not filled with invented quotes. Native expander details contain the eligibility evidence and alternative pairs. Both API prices, bookmaker, snapshot IDs/time, and separately labelled First Observed Price remain traceable.

## Manual quotes and invariants

The form is inside each fixture's existing details expander and stores append-only `manual_ou_quotes` records with source `MANUAL`, real entered line/prices and UTC timestamp. It does not modify `picks`, `odds_snapshots`, `slips`, or mark itself API Main Line. Invalid input is rejected. No event ID means manual saving is unavailable.

Manual EV reuses the existing `score_matrix` and `evaluate_market_poisson` functions, only when an event-coherent B model was recorded within 24 hours, kickoff is in the future, the saved status explicitly names real Understat xG/xGA, expected goals match the saved lambdas, and both venue xG samples have >=5 games with last dates 1–120 days before kickoff. Newly scanned A metadata includes that last date. Old records without provenance stay intact and produce no manual EV until explicitly rescanned. No goals-to-xG substitution or A/C reuse from a different line. Manual EV is an evaluation, not an automatic C recommendation or bill.

Automated tests cover 2.5/2.75/3.0/3.25/3.5, symmetric side selection, ties, missing EV, incomplete/cross-book/cross-scan pairs, ambiguity, bookmaker consensus, alternative-line retention, invalid manual inputs, real/stale/legacy model handling, escaping, old pending/finalized/malformed bills, view changes and offline form submission. Chromium checks light/dark layouts at 320/375/390/430 px. These checks do not substitute for an actual iPhone Safari acceptance test. No settlement, Poisson, EV, A/B/C formula, or API fetch function was changed; four Streamlit tabs remain.
